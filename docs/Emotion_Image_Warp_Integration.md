# 감정 이미지 왜곡(Warp) 연동 정리

> **착수 전 검토 기록이다. 확정 사양이 아니다.**
> 2026-09-19에 기능이 구현됐고, 확정 사양은 `Emotion_Image_Warp_PRD.md`와
> `Emotion_Image_Warp_Implementation_Plan.md`에 있다.
> 아래 §2 감정 6종 재배치와 §2-2 방향별 질감 확장은 **채택하지 않았다.** v1은 프로토타입의
> 6축(`화남/질투/슬픔/포기/황당/서운함`, -120°~180°)을 그대로 쓴다(PRD §18).
> §4 연동 방식은 **A안으로 확정**했다 — FastAPI가 PNG를 만들어 돌려주고 프론트는 Blob으로 표시한다.
> 참고 프로토타입: `sseung63-eng/img-wrap-test` commit `06a7267` (PRD 머리말과 같은 출처로 통일)

## 1. 배경

- AI가 사용자 발화를 분석해 라벨별 `mention_count`와 0~100 정수 `score`를 돌려주고, 서버가 0~1로 정규화하면, 그 값을 이용해 캐릭터/사진 이미지를 감정 방향으로 왜곡시키는 기능을 넣을 예정.
- 왜곡 로직 프로토타입은 `img-warp-test/warp_hexagon.py`에 이미 구현되어 있음 (중심 기준 볼록렌즈 왜곡 + 육각형 6방향 강도 보간).
- 이번에 감정 종류와 배치(시계 방향 위치)를 새로 정의했고, 이를 기존 프로토타입에 반영 후 프로젝트에 연결하는 방향을 잡기 위한 문서.

## 2. 새 감정 구성 (시계 위치 기준)

```
        분노 (12시)  ← 위로 폭발 / 스파이크
      /                  \
 삐짐 (10시)          억울함 (2시)  ← 뜨겁게 밖으로 항변
    |                       |
 답답함 (8시)          서운함 (4시)  ← 안으로 조용히 처짐
      \                  /
        포기 (6시)  ← 아래로 무너짐 / 납작
```

| 감정 | 시계 위치 | 왜곡 방향 이미지 | 비고 |
|---|---|---|---|
| 분노 | 12시 | 위로 폭발 / 스파이크 | 급격하고 뾰족한 돌출 |
| 억울함 | 2시 | 뜨겁게 밖으로 항변 (팽창) | 바깥으로 부풀어 오름 |
| 서운함 | 4시 | 안으로 조용히 처짐 (수축) | 안쪽으로 가라앉음 |
| 포기 | 6시 | 아래로 무너짐 / 납작 | 짓눌리듯 평평해짐 |
| 답답함 | 8시 | (수축/압박 계열, 서운함과 유사한 톤이나 반대편) | 세부 왜곡 파라미터 논의 필요 |
| 삐짐 | 10시 | (분노보다 약한 돌출, 뾰족함 대신 튕기는 느낌) | 세부 왜곡 파라미터 논의 필요 |

기존 `warp_hexagon.py`의 6개 감정(분노/서운함/슬픔/포기/황당/삐짐)에서 **슬픔→억울함, 황당→답답함**으로 교체되고, 배치 각도도 재정렬됨.

### 2-1. 각도 매핑 (화면 좌표계: 오른쪽=0°, 아래=+, 위=-, 기존 `VERTEX_ANGLES_DEG` 규칙과 동일)

시계 위치를 각도로 변환하면 60°씩 균등 배치됨 (정육각형 유지):

| 감정 | 시계 위치 | 각도(deg) |
|---|---|---|
| 삐짐 | 10시 | -150 |
| 분노 | 12시 | -90 |
| 억울함 | 2시 | -30 |
| 서운함 | 4시 | 30 |
| 포기 | 6시 | 90 |
| 답답함 | 8시 | 150 |

→ `warp_hexagon.py`의 `VERTEX_ANGLES_DEG` 딕셔너리 키/값을 이 표대로 교체하면 배치 자체는 그대로 재사용 가능.

### 2-2. 방향별 왜곡 "질감" 차이 (추가 논의 필요)

현재 프로토타입(`warp_image_hexagon`)은 각 꼭짓점 방향의 강도(k)만 다르고, 왜곡 방식 자체(볼록렌즈/스피어라이즈)는 6방향이 동일함.
그런데 새 컨셉은 방향마다 **왜곡의 성질 자체가 다름**:

- 분노(12시): 스파이크형 — 뾰족하게 튀어나옴 (현재 볼록렌즈보다 더 급격한 지수 필요)
- 억울함(2시): 팽창형 — 바깥으로 부풂 (기존 볼록렌즈 왜곡과 유사, 그대로 사용 가능)
- 서운함(4시): 수축형 — 안으로 처짐 (현재 로직의 반대 부호, 오목렌즈)
- 포기(6시): 압착형 — 아래로 눌려 납작해짐 (수직 방향 스케일 축소에 가까움, 방사형 왜곡과 다른 성격)
- 답답함(8시), 삐짐(10시): 세부 정의 미정

→ 단순히 강도(k)만 보간하는 현재 구조로는 "왜곡 성질" 차이를 표현하기 어려움. 방향별로 부호/지수/축 스케일이 다른 왜곡 함수를 섞는 방식(예: 각 정점마다 별도 왜곡 커널을 정의하고 각도 기준으로 blend)으로 확장이 필요해 보임 — 실제 설계는 별도 논의.

## 3. 연동 대상 확인 (착수 시점 기록)

- 착수 시점에는 프론트에 `/api` 호출이 없었다. **현재는** `lib/api/`의 어댑터들이 FastAPI `/api/*`를
  호출하고 AI는 전부 백엔드에 있다(감정 관련은 `lib/api/emotionWarp.ts`).
- 이미지 왜곡 로직은 Python(OpenCV, NumPy) 기반이며, `backend/app/services/warp_hexagon.py`로 이식됐다.

## 4. 연동 방향 후보 — **A안 채택 (2026-09-19)**

| 옵션 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | Python 왜곡 로직을 별도 백엔드 API(FastAPI 등)로 감싸고, 프론트에서 이미지+감정값을 보내 결과 이미지를 받음 | 기존 OpenCV 코드 재사용, 검증된 로직 유지 | 별도 서버/배포 필요, 지연시간 발생 |
| B | 왜곡 로직을 JS/TS로 포팅하여 프론트에서 Canvas/WebGL로 직접 렌더링 | 서버 왕복 없음, 실시간 반응 가능 | 재구현 비용, OpenCV 대비 성능/정밀도 검증 필요 |
| C | AI 분석은 백엔드(또는 Edge Function)에서 감정 변수만 산출 → 프론트가 그 값을 받아 B안처럼 클라이언트에서 왜곡 렌더링 | 책임 분리(AI는 값만, 렌더링은 클라이언트), UX 반응성 좋음 | AI 서버 + 클라이언트 렌더링 두 군데 구현 필요 |
