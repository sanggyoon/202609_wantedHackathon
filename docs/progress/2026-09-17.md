## 4. 판단이 필요했던 항목

기준만으로 정해지지 않는 항목은 따로 확인하고 정했다.

- **고소장 카드 상단 문구.** main은 `{A/B}의 관점 · 저장된 고소장/저장되지 않은 초안`과
  B일 때 `맞 고 소 장`이었고, PR은 `CASE #0241` 고정 문구와 항상 `고 소 장`이었다.
  → **PR 문구를 적용했다.** 그 결과 실제 링크 화면(`/case/[token]`)에서도 저장 여부와
  맞고소장 구분이 표시되지 않는다. `LinkedCaseScreen`이 `saved`를 계속 넘기므로 prop은
  타입에만 남겼다. 사건 번호를 실제 값으로 바꿀 때 함께 정리해야 한다.
- **중재 패널 스타일.** PR은 옛 자리표시자 패널에 스타일을 입혔는데, main은 그 패널을
  실제 AI 결과 컴포넌트로 교체했다. → **PR 스타일을 `MediationSummary`에 옮겨 입혔다.**
  PR의 "중재자의 추천 방안" 자리에 해당하는 것은 main의 "다음 대화의 시작 문장"이다.
- **입력창 자동 높이 조절.** PR이 옛 목업 대화 화면에 추가한 기능이다. CSS가
  `max-height: 120px; overflow-y: hidden`이라 이 코드가 없으면 긴 입력이 잘린다.
  → **실제 대화 화면에 이식했다.**
- **안내 문구.** "화해 성립"의 사건 종결 안내와 개발용 패널의 연결 상태 문구는 실제로
  무엇이 연결됐는지 알려주는 내용이라 로직으로 보고 main 문구를 썼다.

## 5. 병합과 무관하게 고친 것 — lint 에러

CI는 `npm run lint`를 돌린다. PR 원본에 있던 코드가 `react-hooks/set-state-in-effect`에
걸렸다.

```tsx
const [mounted, setMounted] = useState(false);
useEffect(() => {
  setMounted(true);
}, []);
```

포털을 클라이언트에서만 열기 위한 코드다. 효과 안에서 상태를 바꾸지 않도록
`useSyncExternalStore`로 서버/클라이언트를 구분하게 바꿨다. 화면과 동작은 같다.

```tsx
const mounted = useSyncExternalStore(
  () => () => {},
  () => true,
  () => false,
);
```
