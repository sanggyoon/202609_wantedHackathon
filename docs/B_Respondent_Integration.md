# 피고(상대방 B) 흐름 연결 · 2026-09-14

## 범위

PRD §9.4~9.8의 열람 → 사과/맞고소 → 결과 흐름을 현재 브라우저에서 체험하도록 연결했다.
실제 사건 URL, 토큰 권한, DB 저장, 서버 상태 전이, 중복 제출 잠금, 7일 만료는 미연결이다.
따라서 실제 상대에게 전송되거나 보관된다고 표시하지 않는다.

## 맞고소

- A와 B 모두 공통 `LiveConversationScreen` / `useConversation`을 사용한다.
- `/api/complaint/conversation/message`에 `side`(기본 A), B용 `sharedStatement`를 추가했다.
- B의 대화 상태는 빈 상태에서 독립적으로 시작한다. A의 확인 항목을 복사하지 않는다.
- A의 공유 선택·최종 수정 후 카드만 참고 자료로 전달한다. A의 비공개 대화 원문은 전달하지 않는다.
- 추출·발화 모두 A의 주장을 확정 사실로 삼지 않도록 지시한다. B의 명시적 동의·반박을
  B의 진술로 보존하며, 사과나 동의를 필수 조건으로 요구하지 않는다.
- A와 같은 최소 완료 조건(사건 / 감정과 이유 / 바라는 점) 및 INFP 기반 밤톨 말투를 쓴다.
- 진술 수정은 수정 지점 이후 대화를 재작성한다. 완료 후 공유 선택 → 맞고소장 수정·확정 → 양측 카드로 이동한다.

## 양측 중재

- `/api/mediation/report`는 최종 공유 카드 A/B만 받아 구조화된 결과를 반환한다.
- 공통점 / 다른 관점 / 각자의 마음 / 오해 가능성 / 다음 대화 문장으로 구성한다.
- 공통점은 양쪽에서 명시적으로 지지한 내용만 사용하며, 침묵을 동의로 간주하지 않는다.
- 모델 출력은 스키마 검증하지만 의미의 정확성을 완전히 보장하지 않으므로 참고 요약임을 표시한다.
- 키가 없으면 `local` 표시와 함께 각자의 진술만 보여주고 공통점·오해를 만들어내지 않는다.
- 버튼 클릭으로 요청하며 로딩·실패·재시도·이탈 취소를 지원한다. 요청 실패 시 카드는 유지한다.
- API는 결과를 저장하지 않고 `no-store`를 사용하며 제공자 오류의 내부 정보는 숨긴다.

## 사과

- 사과 본문만 필수이며 이해한 점·인정하는 부분·약속은 선택이다.
- B가 직접 작성하고 미리보기·수정한다. AI 생성이나 교정을 수행하지 않는다.
- 제출하면 작성한 내용 그대로 종결 카드에 표시한다. A 수락·거절 단계는 없다.
- 종결은 답변 작성 종료이며 용서나 실제 화해를 뜻하지 않는다.

## 검증

### 감정 주체 보완

- 감정 추출에서 화를 풀어달라는 요청과 말하는 사람의 감정을 구분한다.
- ‘특별한 감정 없음’을 정식 답변으로 인정하며, 이 경우 감정 이유를 요구하지 않는다.
- 감정 없음과 이전 화남을 누적해 모순된 목록을 만들지 않도록 상태 병합을 수정했다.
- 중재 결과의 각자 설명·각자 감정은 공유 카드 그대로 표시한다. AI가 B를 화난 사람으로
  의역하거나 누가 잠들었는지 바꾸는 경로를 차단한다. 오해 가능성은 실제 테스트에서 주체를
  뒤집는 응답이 재현돼 근거 검증 구현 전까지 null로 처리하고 판단 유보 안내를 표시한다.
  공통점·다음 문장은
  여전히 모델 생성이므로 정확성을 완전히 보장하지 않으며 참고 요약임을 유지한다.
- 수정 전 생성된 카드·대화는 자동 재해석하지 않는다. 새 대화로 테스트한다.

- 브라우저에서 예시 A 카드 열람 → B의 실제 OpenAI 대화 → 공유 선택 → 초안 제출 →
  양측 AI 중재 요약 표시까지 확인했다. 별도로 사과 본문만 작성해 원문 그대로 종결되는 것도 확인했다.
- 실제 모델 테스트 중 미래 요청을 과거 기대와 혼동해 재질문한 경우가 있어 추출 지침을 보완했다.
  확률적 추출의 오분류 가능성은 남으며, 완료 판정과 사용자 요약 확인을 함께 사용한다.

- 백엔드 회귀 테스트: B의 상태 분리, A 카드만으로 완료 불가, 동의·사과 없이 완료,
  역할 컨텍스트 전달, 중재 입력 검증·오류 비노출·로컬 모드·공유 카드만 전달.
- 실행: backend 8000 + frontend 3000. `/wireframe`에서 ‘소환장 도착’으로 이동해 두 분기를 테스트한다.
- 개발용 화면 선택기는 검증을 위해 상태를 건너뛸 수 있다. 실제 권한·상태 머신 검증 수단이 아니다.
- 위험 감지·차단 및 실서비스 보안(인증 대신 토큰 검증, 요청 제한)은 별도 작업으로 남는다.
