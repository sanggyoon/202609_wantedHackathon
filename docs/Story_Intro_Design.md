# 받은 고소장 도입문 기획

> 결정일: 2026-09-18  
> 필드: `statement_cards.story_intro`

## 목적

받은 사람이 전체 고소장을 펼치기 전에 갈등의 핵심을 사람 말투로 접하게 한다.
`incident_summary`가 사건명을 위한 한 줄 요약이라면, `story_intro`는 작성자가
상대에게 직접 말하는 귀엽게 삐진 고소 예고다.

## 생성 시점과 입력

`대화 완료 → 공유 항목 선택 → 검토 화면 진입` 시 기존 카드 요약 요청에서
`cute_charge`, `incident_summary`, `story_intro`를 한 번에 생성한다.
추가 AI 호출은 만들지 않는다. 입력은 공유가 확정된 카드뿐이며 대화 원문은 보내지 않는다.
작성자는 검토 화면에서 결과를 수정할 수 있고, 접수한 최종본만 저장한다.

## 출력 규칙

- 자연스러운 한국어 반말 1~2문장, AI 생성 결과는 30~180자
- 작성자가 상대에게 직접 말하는 1인칭 문장
- 구체적으로 서운했던 행동을 먼저 말하고, 동일한 `cute_charge`로 고소한다는 말로 마무리
- 사용자가 이미 정한 유효한 `cute_charge`가 있으면 새로 짓지 않고 그대로 사용
- `~했거든?`, `~서운했어`, `~삐졌어` 등은 실제 감정과 맞을 때만 사용
- 신청인·작성자·상대방·전했습니다·바라고 있습니다 같은 보고서 표현 금지
- 상세 맥락과 원하는 결과는 고소장 안에 남겨, 도입문에서 전부 설명하지 않음
- 공유되지 않은 정보, 새로운 발언·동기·잘못·감정·사과·약속을 생성하지 않음
- 실제 발언도 직접 인용으로 확인할 구조가 없으므로 죄명 외 따옴표 사용 금지
- 모욕·위협·법적 판단 금지

## 예시

입력:

- 사건: 상대가 약속에 늦은 뒤 모든 책임을 내 탓으로 돌렸다고 느꼈다.
- 감정: 서운함, 화남
- 바라는 점: 잘못을 인정하고 먼저 사과해주기

출력:

```json
{
  "cute_charge": "늦었는데내탓죄",
  "incident_summary": "늦은 뒤 책임을 내 탓으로 돌렸다",
  "story_intro": "늦은 것도 서운한데 내 탓이라고 해서 진짜 삐졌거든? 그래서 너를 '늦었는데내탓죄'로 고소할 거야!"
}
```

## 화면

받은 화면은 죄명과 `story_intro`만 먼저 보여준다. 기존 사건 요약·감정·원하는 점의
반복 표시는 제거한다. 고소장 보기에서 구조화된 전체 카드가 펼쳐진다.
기존 데이터나 local 모드처럼 도입문이 없으면 현재 구조형 요약을 대체 표시한다.

## 실패와 검증

- 도입문은 최대 300자까지 작성자가 수정할 수 있다.
- 생성 결과가 30자 미만이거나 180자를 넘거나, 유효한 죄명을 그대로 포함하지 않으면 비운다.
- 생성 실패는 접수를 막지 않으며 재생성 또는 직접 입력이 가능하다.
- 사건 내용을 공유하지 않았으면 도입문은 빈 문자열이다.
- A가 확정한 문장과 B가 읽는 문장이 동일해야 한다.
